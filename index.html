Project Overview

Scalable Web Infrastructure

Traditional web hosting runs on a single server, so a spike in traffic can overload it and take the site down. CloudScale places an Application Load Balancer in front of multiple Amazon EC2 instances so incoming requests are spread across healthy servers, and uses Auto Scaling to automatically adjust how many instances are running based on demand.

Application Load Balancer

A single public entry point that spreads requests across the fleet at the HTTP/HTTPS layer.

  • Distributes incoming traffic
  • Performs health checks
  • Routes requests to healthy instances

Amazon EC2

Virtual servers that run the web application. Every instance serves the identical site.

  • Hosts the web application
  • Multiple instances improve availability
  • Can scale horizontally

EC2 Auto Scaling

Keeps the fleet at the right size, replacing failed instances and following the traffic curve.

  • Maintains desired capacity
  • Adds instances when required
  • Removes unnecessary instances

Scope note

This project deliberately stops at compute, networking and load balancing. No database, storage, CDN or serverless service is used, because the goal is to demonstrate horizontal scaling and high availability on stateless web servers.

Horizontal Scaling

Designed to Scale

Instead of making one server bigger (vertical scaling), CloudScale adds more identical servers (horizontal scaling). When traffic increases, Auto Scaling can launch additional EC2 instances. When traffic decreases, unnecessary instances can be terminated.

Low Traffic

2 EC2 Instances

Baseline capacity — matches the ASG minimum.

Medium Traffic

3 EC2 Instances

Scale-out policy adds one instance.

High Traffic

4+ EC2 Instances

Fleet grows up to the maximum capacity.

    Implementation Plan

    Deployment Workflow

    The ten steps used to take this website from a local folder to a load-balanced, auto-scaled AWS deployment.

    1. 01

      Create VPC

      Provision an isolated network with an internet gateway.

    2. 02

      Configure Subnets

      Create public subnets in two Availability Zones.

    3. 03

      Create Security Groups

      One for the ALB (web traffic) and one for the instances.

    4. 04

      Create EC2 Launch Template

      Base AMI, instance type and user data that installs Apache and the site.

    5. 05

      Create Target Group

      HTTP :80 target group with a health check path of /.

    6. 06

      Create Application Load Balancer

      Internet-facing ALB across both subnets, forwarding to the target group.

    7. 07

      Configure Auto Scaling Group

      Min 2, desired 2, max 4, attached to the target group.

    8. 08

      Register Instances

      The ASG launches instances and registers them as targets automatically.

    9. 09

      Test Application

      Open the ALB DNS name and confirm requests reach both instances.

    10. 10

      Monitor Scaling

      Generate load and observe scale-out, then scale-in as traffic settles.

    Defence in Depth

    Network Security

    Security groups act as virtual firewalls: they control which inbound and outbound traffic is allowed to reach the load balancer and the instances. They are stateful, so a permitted inbound request is automatically allowed to respond.

    Inbound Rules

    Example rule set

    Example security group inbound rules
    TypePortSourcePurpose
    HTTP800.0.0.0/0Public web traffic to the ALB
    HTTPS4430.0.0.0/0Encrypted web traffic to the ALB
    SSH22My IP onlyAdministrative access for setup

    Only these ports are opened. Nothing else is exposed to the internet.

    Practices Applied

    Keeping the surface small

    • The EC2 security group accepts port 80 only from the ALB security group, not from the internet.
    • SSH on port 22 is restricted to a single administrator IP address, never 0.0.0.0/0.
    • Unused ports and protocols are left closed by default — security groups deny anything not explicitly allowed.
    • Instances are stateless, so no credentials or user data are stored on them.
